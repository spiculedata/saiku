feat(demo): backend email-validation gate behind WorkOS Magic Auth (#1029)

Phase 1 (backend) of the demo email gate. In demo mode with WorkOS
configured, a visitor must validate an email (WorkOS Magic Auth 6-digit
code) before reaching the admin/admin login form — light lead capture +
bot filter. Provider-agnostic, and completely inert in production or when
WorkOS keys are absent.

- DemoGateProvider seam + WorkOsMagicAuthProvider (java.net.http, no new dep;
  tolerates WorkOS's empty-body send quirk, needs WORKOS_CLIENT_ID as well as
  WORKOS_API_KEY for /authenticate)
- DemoGateCookie (HMAC-SHA256; HttpOnly/Secure/SameSite=Strict) + DemoGateSecret
  (SAIKU_DEMO_GATE_SECRET or autogen+persist to saiku-home/demo-gate/secret)
- DemoGateFilter (web.xml, before the Spring Security proxy; independent of it)
  + DemoGateResource (/request, /verify, /status) with a per-IP verify rate
  limit reusing LoginRateLimiter
- InfoResource /capabilities now reports emailGate + emailGateProvider
- ~45 JUnit tests: cookie sign/verify/tamper, secret persistence, filter path
  classification, WorkOS client against a JDK HttpServer stub, resource via a
  dynamic-proxy request (no WireMock/Mockito — saiku-web has neither)

Frontend (EmailGateForm + LoginForm gate-first) is Phase 2.
